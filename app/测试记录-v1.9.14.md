# v1.9.14 测试记录

范围：只做滑选页手势手感优化——判定阈值、跟手阻尼、甩动成交、备选卡淡入时长。不改去重、收藏回流、删除与结算逻辑。

环境：`emulator-5554`，API 34，1080×2400，density 420（density 2.625，dp(300)≈788px/s）。`versionCode 24` / `versionName 1.9.14`，同包同签名覆盖安装。

## 一、代码改动

- 横向成交阈值 `w*0.26` → `w*0.18`（1080 宽卡片上约 194px → 约 2.6cm 变 1.8cm 的手感差距）；纵向星标 `h*0.17` → `h*0.12`；纵横主方向判定 `1.35` → `1.25`，斜着划也能比较早认定方向。
- 新增甩动成交：横移超过 `dp(24)` 且 `|vx| > dp(300)`（约 790px/s）、方向与位移一致即成交；纵向上甩超过 `dp(24)` 且 `vy < -dp(260)` 即星标。轻扫不再"滑不动"。
- 跟手：纵向拖动从 `dy*0.92` 改为 1:1；横向拖动时纵向跟随 `dy*0.30` → `0.25`，倾角 `dx/w*9°` → `dx/w*7°`；纵向拖动时横向带 `dx*0.15` 跟随，不再硬锁 0。
- 备选卡淡入 `110ms` → `60ms`，起点不透明度 `0` → `0.72`：滑走正片的同一帧备选就是能看清的，不再先"空一下"再浮现。

## 二、专项回归（`tests/Regression1911Instrumentation.java`）

`测试结果-v1.9.14-instrumentation.txt`，**43 项全部通过**（40 项既有 + 3 项手势）：

- `20 percent horizontal drag commits`：位移 20% 卡宽即成交，历史 +1，当前照片前进。
- `short slow drag snaps back without committing`：10% 卡宽、无速度时强行回弹，不产生动作。
- `fast flick commits below distance threshold`：7% 卡宽但速度为 2000px/s 时成交，验证甩动分支。

既有 40 项（启动备选、淡入三采样、单击行为、连续保留/撤销、去重、黑白齿孔接缝、星标规则四项）继续通过。

`decide` 是视图方法，测试里统一用 `swipeOnce()` 走主线程调用，避免 Instr 线程直接碰视图。

## 四、真实触摸取证

用 `adb shell input swipe` 在滑选页做三组：

- `540→740`、400ms（位移 200px，占 1080 卡宽 18.5%）：保留计数 39→40、当前照片换到下一张、撤销箭头出现。旧版 26% 阈值需要 281px，这一组在旧版不会成交。
- `540→600`、400ms（60px，5.5%）：计数停在 40，回弹不成交。
- `540→660`、80ms（120px）与 `540→690`、100ms（150px）：**都没有成交**。加临时日志读到的速度是 `vx=0 / 217 / -1232`，`input swipe` 注入的事件采样不足以让 `VelocityTracker` 算出真实速度，还出现反向速度。因此甩动分支只有 `decide` 层的数值断言，没有 adb 端到端证据。

## 五、取证的边界

- "跟手"是主观手感，上面能证明的只有阈值变小、阻尼改为 1:1、甩动分支存在；是否真的更顺需要用户上手。
- adb 合成滑动测不出甩动速度（见第四节），真机手指甩动才有几千 px/s 的量级；这一条未做真机验证。
- 模拟器图库只剩历轮测试的合成图，本轮预览截图不交付，避免拿测试图冒充真机预览。
- 真机（荣耀 Magic7）仍无 adb 可达。
